# 反馈闭环

仅记录真实偏差、明确用户纠正或已验证且值得复用的经验。普通成功任务可以只保留简短回执。记录失败与阻塞，成功样本若采样则注明口径。

分类：routing（选错流程）、quality（产物问题）、environment（工具环境）、conflict（规则冲突）、preference（用户偏好）、unknown（根因未明）。

先保留观察、预期、可复现输入、路由 SHA 和脱敏证据，再判断该修改属于项目规则还是跨项目候选。用户明确偏好可以直接形成项目约束；一次偶发失败先验证原因。

默认在对话中草拟反馈。当前请求或项目长期指令明确授权后，才向 hilt21/project-router 创建 Issue，并回读结果。可用的长期授权表述为：“允许将本项目的脱敏路由反馈写入 hilt21/project-router 的 Issues；不得上传完整对话、凭据和业务私密内容。”

本地 `feedback-draft` 只输出正文，不联网、不自动发帖。结构检查和凭据模式检测只能辅助脱敏，最终需审阅白名单字段和引用内容。

改进 PR 附复现、最小修改、反例、旧版与候选版结果、影响范围和回滚方式。模型自评分不构成通过证据。语法检查通过不代表 Work 执行正确。
