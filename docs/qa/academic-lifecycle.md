# 科研生命周期验收与修复

日期：2026-10-25，Asia/Shanghai。范围是已保存研究记录在材料增长、复核和进程恢复中的行为。

## 复现与修复

在 v0.2.0-rc.1 对应实现上，新增证据文件和主张后，旧 coverage 等全局审查会被追溯要求绑定新增材料，导致 `Audit omits required input bindings`。即使已经追加正确的 supersedes 记录，历史条目的校验仍会提前中止，无法完成正常复核。

新增两项回归用例，修复前均复现错误。修复后先根据原摘要判断审查是否过期，保留历史记录的原输入范围；当前 passed 审查仍需覆盖所有适用输入。基本契约、主张账本绑定、passed 的可观察证据与禁止 self-report 独立通过的规则继续生效。

完整本地结果见 [验证记录](academic-lifecycle-verification.json)。执行轨迹见 [生命周期轨迹](academic-lifecycle-trace.json)。命令为 `python evals/run_academic_lifecycle.py`，临时研究文件不会写入用户项目或公开仓库。

轨迹中的 eligible-for-human-review 仅说明合成记录满足登记门槛。其中期刊、原创性和审查的通过状态均为合成夹具，不代表实际期刊合规或论文可以投稿。脚本实际执行的网格检查只验证有限样本，明确不代替一般证明。

已有发布记录保持不可变。修复通过新的候选快照分发；正在进行的研究仍按原工作流 SHA 恢复，升级需要明确记录。真实 Work 新对话、上下文压缩、私有访问和论文效果分别保留待验证状态。
