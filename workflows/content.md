# 渠道内容创作

1. **恢复任务边界**：确认素材、已选主题、受众和本次交付阶段。已有信息不重复询问，历史产物不作为当前事实证据。
2. **核实并提取价值**：读取原文，提取核心事实、证据缺口、真实反差与受众关联。保留主张到来源的对应关系，选择一个能用一句话复述的核心判断。没有检索能力时可以继续结构设计，将待核实正文标清。
3. **选择平台**：根据当前指定和本项目上下文进入 wechat、linkedin 或 dual。无平台时推荐最合适的选项，只在必要时询问。读取所选平台规则，双渠道共用证据并分别重构。
4. **按阶段创作**：使用 `craft-channel-content` 交付下表对应产物，考虑六个传播机制。用户指定一个明确阶段时直接处理该阶段，补足必要核验，不强制逐轮走完整流程。
5. **按单图执行**：若要求 N 张独立图片，先建立 `image_id → 主题 → 视觉 Token → 目标画幅` 的 N 行清单，再逐项单独调用生图工具。每次只请求一个 `image_id` 的一张独立画布（数量参数可用时设 `n=1`），完成后回读和检查该图片，再进入下一张。共享视觉系统可以复用，生成请求与图片文件必须相互独立。
6. **验证交付**：使用 `verify-delivery`。核对事实、篇幅、来源、Hook 是否兑现、图文一致性，以及图片数量、画布独立性、画幅、文字清晰度和主题映射；只把通过验收的图片计入已完成数。若某图变成拼版或产生质量缺陷，标为失败并重做该图；不要裁切冒充独立生成。只有事实准确性及明确交付约束是硬约束，其余按内容优化。
7. **发布与复盘**：只有当前请求明确授权且工具可用时才发布，并回读结果。获得真实数据后使用 content-feedback 模板，形成下一轮实验。出现实质纠正或可复用经验时再加载 `capture-router-feedback`，保留平台与项目作用域。

| 本次阶段 | 交付与完成条件 |
| --- | --- |
| 选题 | 少量差异明确的角度，说明受众关联、核心判断和证据；等待选择，不抢先写成整套。 |
| 单篇正文 | 已选主题直接成稿，只交所请求平台与数量，不默认追加视觉方案。 |
| 视觉方案 | 已有观点或文案对应的视觉 Token，说明图像承担的信息职责，不生成图片。 |
| 直接生图 | 按当前授权执行单图队列；交付清单必须能逐一对应每张独立画布及验收状态，工具结果与质量检查通过后才称已生成，不再增加确认步骤。 |
| 发布 | 核对当前授权、目标平台与最终稿，用真实发布响应和必要回读确认。 |
| 复盘 | 使用真实数据与观察窗口；未发布、无统计时保留 unknown，并提出待验证实验。 |

完成条件：产物符合用户本次指定阶段和渠道，来源可追溯，外部动作有工具确认。编排自身不提供发布工具或生图工具。

## 多图交付检查点

- 例：请求“1 张封面 + 5 张主题图”，清单须包含 6 个 image_id、6 次独立单图生成与 6 张分别检查的独立画布；任何一张拼版裁切的文件都不计为通过。
- 缺少生图工具、调用失败或输出不可检查时，报告实际通过张数与未完成 image_id，不以占位图、未经核实的链接或模型自述填满数量。
- 用户仅要求视觉 Token 时停止在方案阶段；只有明确要求生成图片才调用工具。若用户明确要一张拼版或信息总览，按其要求生成组合画布。
