# 科研工作流

1. **盘点目标与材料**：确认本次请求、research_id、现有材料、工作流 SHA、约束和完成条件。小型单项检查可以在对话中交付；持续研究按科研契约维护可追溯记录。
2. **选择阶段**：以明确请求优先，使用 scope / literature / math / experiment / write / review / submission。select-stage 只盘点并确定下一阶段；不要因稿件、文献与审稿意见同时出现而忽略用户明确意图。
3. **读取并执行**：按该源 SHA 加载路由公共依赖与当前 mode 对应的 skill。工具声明仅作预检，实际工具和目标权限仍需确认。没有可选计算工具时继续推理或设计，计算、复现与渲染明确记为未运行。
4. **维护证据**：登记重要主张、实际来源、假设、推导、代码及运行结果。把主张与证据连接起来，记录具体位置。对缺失、冲突、失败和未知保留显式状态。
5. **检查并交接**：检查阶段交付和实际证据。材料变更后使依赖审查过期，按同一研究 ID 与工作流 SHA 交接。尚未解决的核心问题不能通过语言润色或多数意见消除。
6. **完成本次交付**：使用 verify-delivery，区分阶段完成、审查完成和投稿前置条件。紧凑回执包含 project_id、research_id、工作流 SHA、已读 skills、产物版本、实际验证与未验证项。

## 完整流程

pipeline 由当前材料决定入口，依次协调问题定义、文献与创新、适用的数理与实验、写作、评审修订及投稿检查。数学与实验可相互反馈；证据缺口返回文献或验证阶段，表达问题返回写作。

已授权范围内的内部阶段自动推进并保留交接。需要作者选择研究方向、改变核心假设或缺少决定性材料时，提出最少的必要问题，同时继续独立工作。不要机械复制每阶段确认流程。投稿、付费服务、公开数据和联系他人遵循实际用户授权。

投稿前置检查必须运行两次：首次完整稿之后、最终修订之后。最终检查绑定当前材料，重新覆盖已登记主张与新增修改项，报告分母及未登记风险。已知核心缺陷保持阻断；反复修复没有新证据时报告阻塞与下一步，不能自动豁免。

## 反馈

出现真实路由偏差、用户纠正或可复现的失效时，再加载 capture-router-feedback。默认在当前对话草拟脱敏反馈；公开记录仅包含可复现的规则问题，不上传研究正文或私人数据。
