# 开源调研与 MVP 决策

1. **定义问题**：提取目标、用户、约束和完成条件，列出最可能改变结论的未知项。
2. **收集证据**：使用 `research-open-source`。先广筛，再深入 3 至 6 个最相关项目；必要时保留一个低 stars 但场景高度接近的样本。读取实际源码或关键文件，不能只复述 README。
3. **比较机制**：用相同维度比较架构、依赖、维护状态、许可证、边界、可复用设计。标明查询时间。先用较少依赖解释最小系统。
4. **形成决策**：提出默认选型和替代方案、架构或数据流、MVP 范围、开发顺序及验收方法。对兼容性给出证据或待验证实验。
5. **验证交付**：使用 `verify-delivery`。检查重要结论是否有一手来源，核对限制和授权边界。保留未运行、未访问、未验证项。
6. **记录反馈**：仅在真实偏差、用户纠正或已验证经验出现时读取 `capture-router-feedback`。将候选规则放入审阅流程。

完成条件：用户能用这份材料作出选型决定，并知道先验证什么。若缺少检索能力，可继续问题定义和实验设计；事实性比较标记为阻塞或待核实。
