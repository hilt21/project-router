# 按渠道创作

从当前请求和本项目上下文确定渠道、受众、主题和交付阶段。已有信息不再询问。未指定平台时推荐并说明依据；仅在答案会实质改变交付时询问。双渠道共用事实基础，分别重构观点展开、语言和视觉。

按同一源 SHA 读取 `rules/content.md` 和当前模式的 `rules/content-wechat.md` 或 `rules/content-linkedin.md`；双渠道读取两份。平台参数以这些规则为准，不在本 skill 重复维护篇幅与画幅。

## 形成一个传播判断

读取原始材料，为关键主张保留出处与证据性质。核实最新事实；将作者观点、访问印象、比喻和自己的推断标清。只引用非中文来源，不编造经历、数字、直接引语、动机和因果。来源不足时缩小主张，无法核实时标记缺口。

确定受众为什么关心、真实反差在哪里、读完新增什么、凭什么可信、为何值得分享、如何强化长期定位。选择最强的一个角度，用一句话表达核心判断。避免堆积观点，也不把这六项逐项写进发布正文。

让 Hook 引出明确的信息缺口，用正文中的事实或案例及时兑现，接上边界清楚的个人判断。用短段落、具体句子和稳定术语，避免固定否定转折模板和破折号。

## 阶段和交付

只要求选题时交少量方向及差异；已选择主题时直接写稿；只要单篇正文时交正文。检查平台参数，当前用户指定长度或画幅优先。

需要图片时先明确它展示证据、解释机制或降低哪项理解成本。视觉 Token 包含构图、主体、层级、配色、字体、关键文字、图文关系和平台适配。默认先交方案；当前用户要求直接生成时在内部完成规划，立即检查并调用宿主生图工具，不额外等待确认。精确数据图使用绘图工具。

## 多图执行契约

收到 N 张独立图片的请求时，先列出 N 个稳定 `image_id`（如 `cover`, `topic-01` 至 `topic-05`），为每个 ID 编写只描述这一张图片的视觉 Token。建立 `image_id / 主题 / 画幅 / 生成结果 / 验收状态` 清单。

逐张发起独立生成调用；一次调用只处理一个 `image_id`，工具有数量参数时指定 `n=1`。禁止在一个提示词中要求输出六宫格、拼贴、分屏、多主题画布；禁止把一张拼版图裁切后声称已经分别生成。共享风格可以通过复用视觉 Token 表达。若生成器把多个主题放到同一张画布，检查失败，重写该单张提示词后重试。除非用户本次明确要求一张组合图，否则不可将其作为合格输出。

每次调用后检查该图的主题、构图、指定画幅、中文文字可读性与图像独立性；仅通过检查的图片进入交付清单。工具不可用或无法检查时，报告 `failed` 或 `unknown`，保留剩余 image_id，不用虚构路径或占位符补齐。

逐项检查停留、价值、可信、记忆、分享和关注。优先修正证据和 Hook 承诺，再压缩文字与图片。无明确传播收益时重新定义角度，不用机械总分代替判断。

只对有真实工具结果的操作声称已生成或已发布。复盘时按 `templates/content-feedback.md` 记录观察窗口和实际数据；缺失值保留 unknown，无数据时只提出实验，不声称传播提升。
